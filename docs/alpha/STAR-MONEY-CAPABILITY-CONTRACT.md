## 0. 唯一目标

STAR 不再以研究页面完成度为主线。

唯一目标：

> 能否持续产生可执行、可复验、扣除成本后为正的交易决策。

「赚钱能力」不是系统声称能赚钱，而是：

```text
不偷看未来
+ 计入滑点
+ 计入失败退出（无法卖出 ≈ 归零）
+ 策略版本冻结、不得回改旧规则冒充历史成绩
→ 样本外净期望仍为正
```

未通过 M3 之前，禁止称 STAR「具备初步赚钱能力」。  
未通过 M4 之前，禁止讨论投入真钱。  
此前六页面与单测只证明工程存在，不证明能赚钱。

资金权限保持：`DENIED`。无杠杆、不借款、不自动交易、不接触偿债资金。

## 2. 产品目标与唯一输出

在 Solana 新发行代币中，尽早识别：

- 哪些不能买
- 哪些已经太晚
- 哪些具有可成交的非对称赔率
- 何时进入
- 最大可买多少
- 什么条件必须退出
- 最终能否真实卖出

每天只输出：

```text
今日可行动候选：0—3 个
观察候选：若干
明确禁止：其余全部
```

每个可行动候选必须包含：

| 输出 | 内容 |
| --- | --- |
| 决策 | `AVOID` / `WATCH` / `ACTIONABLE` |
| 进入窗口 | 可接受价格与失效时间 |
| 最大容量 | 按池深、滑点和可退出量计算 |
| 机会依据 | 资金、筹码、叙事、团队、时机 |
| 硬风险 | 铸币、冻结、权限、集中度、关联钱包 |
| 失效条件 | 什么事实出现立即否决 |
| 退出方案 | 分段退出、时间退出、流动性退出 |
| 证据时间 | 当时真正可见的信息 |
| 置信等级 | 数据完整度与模型可靠性 |

迟到信号和数据缺失默认不交易。

## 3. 时间与禁止未来信息

每条记录必须带：

```text
append-only
+ observed_at
+ effective_at
+ ingested_at
+ source
+ raw_receipt
+ collector_version
```

决策只能使用 `observed_at / ingested_at / effective_at ≤ as_of` 的对象。  
无时间戳的实体关系 fail-closed，不得编造可见性。

历史回灌若无法恢复真实处理时长：

```text
timing_quality = BACKFILLED_UNKNOWN
completed_at = ingested_at
不得编造 started_at
不得进入实时成功率 / 延迟分母
```

HISTORICAL 必须冻结完整对象：

```text
HistoricalEvaluationContext
├── as_of, normalized_facts, narrative_snapshot, lifecycle_events
├── entity_relations, eligibility_policy_version, scoring_policy_version
├── evidence_cutoff, evaluation_engine_version
```

不得把当前项目缓存（lifecycle / narrative 列）当作当时可见事实。

## 4. 收益口径（独立 Oracle，禁止自证）

生产引擎不得定义什么叫成功。对每个代币独立计算：

- 进入后最大涨幅 MFE
- 最大回撤 MAE
- 达到 2x / 5x / 10x 所需时间
- 是否发生 rug
- 是否无法卖出
- LP 最大撤出幅度
- 可实现退出价格
- 扣除滑点后的实际收益
- 7 天、14 天后的最终状态
- 若按退出规则执行，真正能拿到多少

必须区分：

```text
图表最高涨幅
≠ 可成交收益
≠ 账户真实收益
```

一个币盘中涨 100 倍，但仓位只能以 3 倍价格退出，系统收益只能记 3 倍。  
无法卖出的项目必须按近似归零计算。

## 5. 语料与采样

原来的「50 成功 + 100 失败」只够合同测试，不足以证明赚钱能力。

### 快速批：最近 90 天

采集 Solana 全部符合基础流动性要求的新池，而不是人工挑选成功币。

### 完整批：至少跨越三个市场状态

必须覆盖热点扩张期、高位拥挤期、冷却衰退期。最终至少需要数百至上千个连续出现的项目。

采样原则：

> 先冻结时间范围，再收集这个时间范围内的全部合格项目。

禁止只采集知名成功项目。合成 150 与夹具 ≠ 历史语料。`REAL DATA` 在 M1 完成前 = `NO-EVIDENCE`。

## 6. Baseline（先于任何自由 AI 决策）

```text
发现新池
→ 等待最小观察期
→ 安全门禁
→ 流动性门禁
→ 筹码门禁
→ 资金流门禁
→ 时机门禁
→ 候选排序
→ 模拟进入
→ 规则退出
```

固定三个评估点：首次可交易后 15 分钟、1 小时、6 小时。  
最大持有周期先设为 7 天。

先让数据回答「什么时候买」，不要凭经验冻结。

## 7. 第一版赚钱能力门槛

STAR 只有同时通过以下指标，才能声称形成初步 Alpha（= 通过 M3）：

### 数据门槛

- 决策所需字段覆盖率 ≥ 95%
- 每条结论可追溯到原始回执
- 历史回放无未来信息
- 买入和卖出均有点时流动性证据

### 策略门槛

- 样本外净期望为正
- 扣除滑点、手续费后 Profit Factor ≥ 1.3
- 至少在多个时间窗口为正
- 收益不能依靠单个百倍币
- 前五大盈利交易不能贡献绝大多数利润
- 最大回撤必须处于预设风险预算内

### 可执行门槛

- 95% 以上模拟订单能够按模型价格区间成交
- 退出容量覆盖计划仓位
- 无法卖出 ≈ 归零
- 迟到信号和数据缺失默认不交易

门槛随后按真实分布校准，不得为了通过测试降低标准。

## 8. 四个引擎

1. **Discovery Engine** — 全市场发现，而不是只研究已经知道的项目。
2. **Survival Engine** — 先排除貔貅、权限、关联出货、LP、伪造交易、极端集中、无法退出。
3. **Opportunity Engine** — `上涨空间 × 成功概率 × 可投入容量 × 可退出概率 ÷ 当前拥挤程度`。
4. **Execution & Learning Engine** — 记录当时建议、模拟成交、实际路径、门禁有效/失效；策略版本必须冻结。
